# Answer key: course3_capstone_extract.csv

`course3_capstone_extract.csv` is a vendor extract for 2026-07-01 to 2026-10-02 with these problems planted on purpose. Generated by `tools/make_course3_data.py` with seed 20261005. The clean extract has 66 rows, one per market day (the dates of `treasury_par_yields.csv` in the period); the file has 69 rows. No row carries two problems, and the first two and last two market days are clean. In every row with a planted problem, every other value is clean.

Clean values: the four yield columns equal `treasury_par_yields.csv` (percent, as Treasury published them) and the two spread columns equal `course3_synthetic_spreads.csv` (bp, synthetic) on every market day. Yields are in percent and spreads in bp.

## A holiday row with `.` in every value (1 row)
2026-09-07 has no row in the Treasury file: the market had no curve that day. The vendor sent the date with `.` in every value column, as FRED marks a weekday with no value. Fix: read `.` as missing and drop the row. Never turn `.` into 0.
- `2026-09-07`: in the file . in every value column; clean: no row

## A weekend-dated row (1 row)
A Saturday carrying the values of the Friday before it. Fix: drop the row; a weekend is never a market day.
- `2026-08-08`: in the file the values of 2026-08-07; clean: no row

## A missing market day (1 row)
A date with a row in the Treasury file is absent from the extract. Fix: report it. The row is restored from the clean source (the Treasury file and the synthetic spreads file); it is never forward filled, which would invent a zero change.
- `2026-07-16`: in the file no row; clean: 4.16, 4.28, 4.57, 5.09, 99.1, 332.5

## Exact duplicate rows (2 rows)
Each of these dates appears twice, the second row an exact copy directly below the first. Fix: remove the copies.
- `2026-09-11`: in the file the row twice; clean: one row
- `2026-09-15`: in the file the row twice; clean: one row

## Dates written MM/DD/YYYY (3 rows)
Every other date is ISO `YYYY-MM-DD`. Fix: parse these with the format `%m/%d/%Y`. Parsing the whole column with one format fails on them, which is how they are found.
- `2026-07-20`, `date`: in the file `07/20/2026`, clean value `2026-07-20`
- `2026-08-14`, `date`: in the file `08/14/2026`, clean value `2026-08-14`
- `2026-09-04`, `date`: in the file `09/04/2026`, clean value `2026-09-04`

## A spread in percent instead of bp (2 rows)
The value is a hundredth of the clean figure, so it sits far below every other spread. Fix: multiply by 100 and round to 1 decimal.
- `2026-08-18`, `ig_spread_bp`: in the file `0.957`, clean value `95.7`
- `2026-09-18`, `hy_spread_bp`: in the file `3.251`, clean value `325.1`
